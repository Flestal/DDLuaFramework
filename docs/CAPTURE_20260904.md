## Located engine points

The byte signatures and RVAs are recorded in
`runtime/config/game_bridge_profiles.ini`. They are valid only after the main
executable hash resolves to this build profile and every signature byte matches.

### Named effect dispatcher — RVA 0x005FE960

Resolves an effect name, constructs its effective target list, calls the
per-target effect routine, and finally emits `TrinketTriggeredEvent` when the
target list is non-empty.

Observed arguments:

- RCX: battle object
- RDX: effect-name string
- R8: performer actor
- R9: primary target actor

This is the narrowest point for recognizing the exact marker effects named
`Flestal Rekindled ... Trigger Burn`.

### Per-target effect application — RVA 0x005FEC40

Called once for each resolved effective target.

Observed arguments:

- RCX: battle object
- RDX: performer actor
- R8: primary target actor
- R9: effective target actor

While the named marker dispatcher is active, this point can collect the unique
R9 actors selected by `target_group` without trying to reproduce the game's
targeting rules.

### Native Burn DoT tick — RVA 0x005FDE30

Observed arguments:

- RCX: battle object
- RDX: actor

The routine sums active Burn entries, applies exact damage, displays the Burn
popup, and performs the normal death checks. Buff-duration decrement is handled
later by the battle state machine, not by this routine.

### Proposed safe bridge sequence

1. Match only the exact third marker name in the named effect dispatcher.
2. Let the original dispatcher and its per-target calls finish while collecting
   unique effective-target actor pointers.
3. After the marker returns, call the native Burn DoT tick once for each captured
   living target.

Deferring the Burn calls until the dispatcher returns avoids mutating or killing
actors while the engine is still iterating its effect target vector. It also
preserves the requested order: Burn 2, Burn-decay debuff, then forced Burn tick.

## Other combat mechanics mapped so far

These are useful landmarks, but they are not yet equivalent to the verified
callable Burn tick above.

- Poison/blight uses the internal name `poison`. Its effect parser field
  `.dotPoison` is referenced at RVA `0x004E66D9`, and the Actor status predicate
  is at RVA `0x004774C0`.
- Bleed's `.dotBleed` parser field is referenced at RVA `0x004E66F3`, and the
  Actor status predicate is at RVA `0x00477560`.
- Burn's Actor status predicate is at RVA `0x00477600`.
- Poison and bleed presentation selection occurs in the shared routine beginning
  at RVA `0x0076B4E0`; this is not the damage-application routine and must not be
  used to force a tick.
- Surprise has distinct battle states `bs_before_surprise` and `bs_surprise` and
  separate party/monster surprise data. The text/config registration area around
  RVA `0x007450C2` is only a serialization landmark, not a safe mutation API.

Consequently, Burn is currently the only DoT with a verified full native
damage/popup/death call contract. Poison, bleed, and surprise need another
targeted runtime trace before they can be exposed as safe callable bridges.
